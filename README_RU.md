mGBA
====

mGBA — эмулятор для запуска игр Game Boy Advance. Он стремится быть быстрее и
точнее многих других эмуляторов GBA, а также добавляет возможности, которых
нет в других эмуляторах. Также поддерживаются игры Game Boy и Game Boy Color.

Актуальные новости и загрузки доступны на [mgba.io](https://mgba.io/).

[![Build status](https://buildbot.mgba.io/badges/build-win32.svg)](https://buildbot.mgba.io)
[![Translation status](https://hosted.weblate.org/widgets/mgba/-/svg-badge.svg)](https://hosted.weblate.org/engage/mgba)

Возможности
-----------

- Высокая точность эмуляции железа Game Boy Advance[<sup>[1]</sup>](#missing).
- Поддержка железа Game Boy и Game Boy Color.
- Быстрая эмуляция. Известно, что работает на полной скорости даже на слабом
  железе, например нетбуках.
- Порты на Qt и SDL: тяжёлый и лёгкий фронтенды.
- Поддержка локального (в пределах одного компьютера) кабеля связи.
- Определение типа сохранения, включая размер флеш-памяти[<sup>[2]</sup>](#flashdetect).
- Поддержка картриджей с датчиками движения и вибрацией (работает только с
  игровыми контроллерами).
- Поддержка часов реального времени без дополнительной настройки.
- Поддержка солнечного датчика в играх Boktai.
- Поддержка Game Boy Camera и Game Boy Printer.
- Встроенная реализация BIOS, а также возможность загружать внешние файлы BIOS.
- Поддержка скриптов на Lua.
- Ускорение/перемотка вперёд по удержанию Tab.
- Перемотка назад по удержанию клавиши Backquote.
- Пропуск кадров с настройкой до 10.
- Снимки экрана.
- Поддержка кодов читов.
- 9 слотов сохранений. Сохранения также можно просматривать как снимки экрана.
- Запись видео, GIF, WebP и APNG.
- Поддержка e-Reader.
- Переназначаемые клавиши как для клавиатуры, так и для геймпадов.
- Загрузка из файлов ZIP и 7z.
- Поддержка патчей IPS, UPS и BPS.
- Отладка игр через интерфейс командной строки и поддержка удалённой отладки
  GDB, совместимая с Ghidra и IDA Pro.
- Настраиваемая перемотка эмуляции.
- Поддержка загрузки и экспорта снимков GameShark и Action Replay.
- Ядра доступны для RetroArch/Libretro и OpenEmu.
- Переводы, предоставленные сообществом, для нескольких языков через
  [Weblate](https://hosted.weblate.org/engage/mgba).
- И ещё очень много всего меньшего.

### Системные требования

Требования минимальны. Подойдёт любой компьютер, работающий под Windows Vista или
новее. Также требуется поддержка OpenGL 1.1 или новее; для шейдеров и расширенных
возможностей нужен OpenGL 3.2 или новее.

Управление
---------

Управление настраивается в меню настроек. Многие игровые контроллеры должны быть
распознаны и сопоставлены автоматически. Управление с клавиатуры по умолчанию:

- **A**: X
- **B**: Z
- **L**: A
- **R**: S
- **Start**: Enter
- **Select**: Backspace

Сборка
------

Для сборки требуется CMake 3.1 или новее. Известно, что mGBA собирается с
помощью GCC, Clang и Visual Studio 2019.

#### Сборка через Docker

Рекомендуемый способ сборки для большинства платформ — Docker. Предоставлено
несколько образов Docker, содержащих необходимый тулчейн и зависимости для
сборки mGBA на разных платформах.

Примечание: если у вас более старая версия Windows до Windows 10, возможно, потребуется
настроить Docker на использование общих папок VirtualBox, чтобы корректно
сопоставить текущую директорию `mgba` с рабочей директорией образа. Подробнее —
в задаче [#1985](https://mgba.io/i/1985).

Чтобы собрать mGBA через образ Docker, выполните следующую команду в корне
checkout'а mGBA:

	docker run --rm -it -v ${PWD}:/home/mgba/src mgba/windows:w32

После запуска контейнера он создаст директорию `build-win32` с результатами
сборки. Замените `mgba/windows:w32` на другой образ для других платформ — будет
создана соответствующая директория. Доступные образы на Docker Hub:

- mgba/3ds
- mgba/switch
- mgba/ubuntu:xenial
- mgba/ubuntu:bionic
- mgba/ubuntu:focal
- mgba/ubuntu:groovy
- mgba/vita
- mgba/wii
- mgba/windows:w32
- mgba/windows:w64

Чтобы ускорить сборку, добавьте флаг `-e MAKEFLAGS=-jN` для параллельной сборки с
`N` числом ядер CPU.

#### Сборка в *nix

Для сборки через CMake в Unix-подобной системе рекомендуются такие команды:

	mkdir build
	cd build
	cmake -DCMAKE_INSTALL_PREFIX:PATH=/usr ..
	make
	sudo make install

Это соберёт и установит mGBA в `/usr/bin` и `/usr/lib`. Установленные
зависимости будут обнаружены автоматически, а отключённые из-за отсутствия
зависимостей возможности будут показаны после запуска `cmake` вместе с
предупреждениями о ненайденных зависимостях.

В macOS шаги немного отличаются. Предполагая, что вы используете пакетный
менеджер Homebrew, рекомендуемые команды для получения зависимостей и сборки:

	brew install cmake ffmpeg libzip qt5 sdl2 libedit lua pkg-config
	mkdir build
	cd build
	cmake -DCMAKE_PREFIX_PATH=`brew --prefix qt5` ..
	make

Обратите внимание: в macOS не следует выполнять `make install` — это не
сработает корректно.

#### Сборка на Windows для разработки

##### MSYS2

Для сборки на Windows в целях разработки рекомендуется MSYS2. Следуйте шагам
установки на их [сайте](https://msys2.github.io). Убедитесь, что используете
32-битную версию («MSYS2 MinGW 32-bit») или 64-битную («MSYS2 MinGW 64-bit»),
если нужна сборка под x86_64, и выполните эту дополнительную команду (включая
фигурные скобки) для установки необходимых зависимостей (учтите, что это
означает загрузку более 1100 МиБ пакетов, поэтому процесс займёт долгое время):

	pacman -Sy --needed base-devel git ${MINGW_PACKAGE_PREFIX}-{cmake,ffmpeg,gcc,gdb,libelf,libepoxy,libzip,lua,pkgconf,qt5,SDL2,ntldd-git}

Получите исходный код:

	git clone https://github.com/mgba-emu/mgba.git

Затем соберите, выполнив эти команды:

	mkdir -p mgba/build
	cd mgba/build
	cmake .. -G "MSYS Makefiles"
	make -j$(nproc --ignore=1)

Обратите внимание: такая сборка mGBA для Windows не подходит для распространения
из-за множества разбросанных DLL, необходимых для работы, но идеально подходит
для разработки. Однако если такую сборку всё же нужно распространять (например,
для тестирования на машинах без установленного окружения MSYS2), выполнение
`cpack -G ZIP` подготовит zip-файл со всеми необходимыми DLL.

##### Visual Studio

Сборка через Visual Studio — такая же сложная настройка. Для начала нужно
установить [vcpkg](https://github.com/Microsoft/vcpkg). После установки vcpkg
понадобится установить несколько дополнительных пакетов:

    vcpkg install ffmpeg[vpx,x264] libepoxy libpng libzip lua sdl2 sqlite3

Обратите внимание: эта установка не поддерживает аппаратно-ускоренное
кодирование видео на оборудовании Nvidia. Если это важно, сначала установите
CUDA и замените `ffmpeg[vpx,x264]` на `ffmpeg[vpx,x264,nvcodec]` в предыдущей
команде.

Также потребуется установить Qt. К сожалению, поскольку Qt принадлежит
угасающей компании, а не разумной организации, офлайн-установщик с открытым
исходным кодом для последней версии больше не существует. Придётся либо
использовать [старый установщик](https://download.qt.io/archive/qt/5.12/5.12.9/qt-opensource-windows-x86-5.12.9.exe)
(который требует создать бесполезный аккаунт, но это можно временно обойти,
отключив сеть или задав неверный прокси), либо онлайн-установщик (который
в любом случае требует аккаунт), либо собрать Qt через vcpkg (медленно).
Ни один из вариантов не идеален. Для установщика нужно выбрать подходящие версии
MSVC. Обратите внимание, что офлайн-установщики не поддерживают MSVC 2019.
Для vcpkg нужно установить так, что займёт довольно много времени, особенно на
четырёхъядерных компьютерах и медленнее:

    vcpkg install qt5-base qt5-multimedia

Затем откройте Visual Studio, выберите Clone Repository и введите
`https://github.com/mgba-emu/mgba.git`. Когда Visual Studio закончит клонирование,
перейдите в File > CMake и откройте файл CMakeLists.txt в корне скачанного
репозитория. После этого mGBA можно разрабатывать в Visual Studio так же, как
другие CMake-проекты Visual Studio.

#### Сборка для консолей

Если у вас есть devkitARM (для 3DS), devkitPPC (для Wii), devkitA64 (для
Switch) или vitasdk (для PS Vita), используйте следующие команды:

	mkdir build
	cd build
	cmake -DCMAKE_TOOLCHAIN_FILE=../src/platform/3ds/CMakeToolchain.txt ..
	make

Замените параметр `-DCMAKE_TOOLCHAIN_FILE` для следующих платформ:

- 3DS: `../src/platform/3ds/CMakeToolchain.txt`
- Switch: `../src/platform/switch/CMakeToolchain.txt`
- Vita: `../src/platform/psp2/CMakeToolchain.vitasdk`
- Wii: `../src/platform/wii/CMakeToolchain.txt`

### Зависимости

У mGBA нет обязательных зависимостей, однако для отдельных возможностей нужны
следующие необязательные зависимости. Если зависимость не найдена, соответствующая
возможность отключается.

- Qt 5: для GUI-фронтенда. Для звука нужен Qt Multimedia или SDL.
- SDL: для более простого фронтенда и поддержки геймпада в Qt-фронтенде.
  Рекомендуется SDL 2, но поддерживается и 1.2.
- zlib и libpng: для снимков экрана и сохранений в формате PNG.
- libedit: для отладчика командной строки.
- ffmpeg или libav: для записи видео, GIF, WebP и APNG.
- libzip или zlib: для загрузки ROM, упакованных в zip.
- SQLite3: для баз данных игр.
- libelf: для загрузки ELF.
- Lua: для скриптов.
- json-c: для API скриптинга `storage`.

SQLite3, libpng и zlib входят в состав эмулятора, их не нужно собирать
отдельно.

## Наш форк

Этот репозиторий — форк mGBA с локальными изменениями для задач автоматизации
(трассировка ROM, дампы памяти). Поведение апстрима сохранено везде, кроме
перечисленного ниже.

### Состояние платформ

**Проверен только Windows, и не полностью:**

| вариант | состояние |
|---|---|
| `mgba-headless.exe` | работает, полностью статический, скриптинг есть |
| `mgba-sdl.exe` | собирается, скриптинг есть |
| `mGBA.exe` (Qt) | не запускается, конфликт ABI компиляторов |

Другие платформы (Linux, macOS, консоли) из этого форка не собирались и не
проверялись. Всё ниже относится только к Windows.

### 1. Починка TLS для Windows

`include/mgba-util/common.h` задаёт `_WIN32_WINNT` как `0x0601` (Windows 7),
где нет `InitOnceExecuteOnce`. Вызовы в `src/core/log.c`, `src/core/thread.c`
и `src/script/context.c` уходили в отсутствующий импорт и роняли любой
headless-запуск с `0xC0000005` до загрузки ROM.

Заменено на `TlsAlloc`/`TlsGetValue` под защитой
`InterlockedCompareExchange`.

### 2. Новые методы скриптов

| метод | назначение |
|---|---|
| `emu:hashRange(addr, length)` | CRC32 диапазона, из `mgba-util/crc32.h`. Детект изменений без передачи данных |
| `emu:findBytes(pattern, addr, len)` | Поиск шаблона. Возвращает строку, адреса по 4 байта LE. Отказ при длине > 64 МиБ |
| `emu:dumpRange(path, addr, len)` | Запись диапазона в файл. Возвращает байты или -1/-2 |
| `emu:stop()` | Завершение процесса с кодом 0 |
| `emu:pressKey(id)` | Нажать и удерживать кнопку |

### 3. Флаг `-L`

Короткий алиас для `--script`, чтобы скрипт передавался из командной строки без
config-файла. Именно `-L`, а не `-l`: mGBA уже использует `-l` для `--log-level`.

### 4. `print` сбрасывает буфер

`print()` вызывает `fflush(stdout)`. Раньше вывод терялся при убийстве процесса
с перенаправленным stdout, потому что stdio буферизует блоками.

### 5. `DISABLE_UPDATER` включён по умолчанию

Форк не автообновляется, сборки идут из CI. `updater-stub` отключён; опция
находится в `CMakeLists.txt`.

### 6. Исправление переполнения в `findBytes`

`length * 4` считалось в uint32, и при длине выше `0x40000000` размер
переполнялся, а первое же совпадение писало за пределы буфера. Теперь стоит
лимит 64 МиБ и граница цикла, которая не переполняется.

### Проверенное поведение, о котором стоит знать

`emu:read16` и `emu:read32` читают **little-endian**, независимо от
endianness шины GBA. На байтах `DE AD BE EF` дают `0xADDE` и `0xEFBEADDE`.

`hashRange` совпадает с `zlib.crc32`: обе дают `0x7C9CA35A` на `DE AD BE EF`.

### Известные ограничения

- `emu:runFrame()` и `emu:frameCycles()` роняют Lua-контекст, `pcall` не спасает.
- `emu:screenshot()` роняет контекст тоже: скрипты выполняются до инициализации
  видеобуфера ядра. Не исправлено.
- `findBytes` и `hashRange` читают через `busRead8` вместо существующего
  `mCoreMemorySearch`, что на скане 32 МБ на 1–2 порядка медленнее. Не измерено.
- Qt-фронтенд не запускается: Qt собран MinGW-Builds GCC 13.1, форк — MSYS2
  GCC 16.2, ABI несовместимы.

### Тесты

`tools/mgba-headless/tests.lua` покрывает новые методы: 46 проверок, 0 падений.
Запуск:

```cmd
mgba-headless.exe -L tests.lua "path\to\game.gba"
```
